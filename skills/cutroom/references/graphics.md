## 1. How the film works

Start with the [reusable components](components.md), [format-aware layouts](layouts.md), and
[rendered visual gallery](../examples/gallery/README.md). Use the low-level API below when the shotlist calls for
a custom graphic. Components inherit the current profile; the gallery's palette is an example only.

`film/index.html` loads `data.js` (generated by `sync.py`), then `runtime.js` (the engine), `layouts.js`,
`components.js`, then `film.js` (your
film). The film is a pure function of time: `window.seek(t)` paints frame t, and the renderer calls it for every
frame in any order. The footage is a JPG sequence swapped per frame, so it stays frame-exact.

Layer order = the order you create things: `R.footage()` first (bottom), then scenes, then captions (top).
Times are **seconds in the cut** (from `edit/words.json`). Time graphics to the word that triggers them.

## 2. Engine API (`window.R`)

| | |
|---|---|
| `R.W, R.H, R.FPS, R.DUR` | canvas size, fps, duration |
| `R.footage()` | adds the footage layer (call once, first) |
| `R.frameFootage({zoom, focus:[x,y], card, rect:{x,y,w}, radius})` | frame the footage this frame. `zoom` punches in around `focus` (the face). `card` (0→1) collapses the footage into a rounded card at `rect`, which makes room for a big graphic below. Call it from `R.before.push(t => …)` |
| `R.scene({name, from, to, build(root, S), run(t, S)})` | a beat. The root is shown on [from, to); `build` makes the DOM once; `run` animates every frame |
| `R.make(tag, css, parent, html)` | create an element (in `build` only) |
| `R.keep(el, base)` | register an animated element. Hidden until shown: `keep(el, {o: 0})` |
| `R.set(el, {x, y, s, sx, sy, r, o, hide, clip, filter, text, html, style:{}})` | this frame's props. Anything not set returns to its base |
| `R.hit(t, at, preset)` | 0→1 spring that READS on time `at` (led by half its travel). Use it for anything tied to a word or a sound |
| `R.spring(t, at, preset)` | 0→1 spring released at `at` (exits, things without a sound) |
| `R.track(t, [[t0, v0], [t1, v1, preset], …])` / `R.trackXY` | a value with several targets: each change is its own spring and keeps momentum. Use it for camera zoom, cursor paths and counters that retarget |
| `R.between(t, tIn, tOut)` | 1 inside the window, with spring edges |
| `R.pop(t, el, tIn, tOut, {dy, s0, preset, x, y})` | the standard card enter (rise + scale, opacity only rides along) and exit (lift + shrink) |
| `R.line(parent, text, {x, y, size, width, align, color, accent:[i], weight, font})` → `R.rise(t, L, times, tOut)` | masked kinetic type: words rise through a mask on their own times and lift out |
| `R.typeText(t, el, text, t0, t1)` | typewriter |
| `R.captions(words, cfg)` → `.run(t, {y, hidden})` | captions in the profile's style (`project.json.captions`) |
| `R.prog(t, t0, t1)`, `R.ease.out/inOut`, `R.clamp`, `R.lerp`, `R.rng(seed)` | linear progress (for typing, counters and slow pushes only), easing for those, and seeded randomness |
| `R.before.push(fn)`, `R.after.push(fn)` | per-frame hooks (camera, captions) |
| `R.fonts.push('700 100px Display')` | fonts awaited before frame 0 |

CSS variables from the profile: `--text --ink --muted --accent --card --panel --line --display --ui --mono`.
The `.c` class means absolutely positioned with a centre transform origin, and `.pill` is a rounded flex row.

Spring presets: `snap` for chips, buttons and leading edges (tiny overshoot); `smooth` for cards, panels and the camera;
`heavy` for big type and lockups (no overshoot); `bouncy` for playful accents only.

## 3. Motion rules

These exist because they're what separates "edited" from "template":
- **Springs for everything that enters, exits or retargets.** No CSS transitions, `setTimeout`, `requestAnimationFrame`
  or `Math.random` (they break the frame-exact render). Linear progress only for typing, counters and slow pushes.
- **An enter is never only a fade.** It's a rise, scale, mask reveal, slide or type-on; opacity only rides along.
  The same goes for exits.
- **One thing leads.** In a group, stagger the entries by 0.05–0.12 s, and lead with the element tied to the word.
- **Exits are quick** (~0.15–0.25 s) and finish before the next thing lands: no double exposure at swaps.
- **No overshoot on type.** A tiny overshoot on UI chips and buttons is fine. Bouncy only if the profile says so.
- **2D transforms only.** No `translate3d`, `translateZ`, `will-change` or 3D rotation (composited layers paint
  differently depending on the previous frame). Check with `render.mjs --verify`.
- **Never** (unless the profile asks): glow, light leaks, spins, glitch, crossfades, generic particle bursts, a
  centred title on a gradient, corner labels, frame borders, or dead time with nothing changing.

## 4. Layout and readability

- **Phone first.** Judge every frame at 360 px wide (`review/sheet_phone.jpg`). Body text on cards ≥ 34 px, labels
  ≥ 28 px, numbers and hero type 90–220 px at 1080 wide.
- **Don't cover the face.** On talking heads the face is in the top ~45 %. Graphics go in the chest band (about
  y 900–1400 of 1920). For big moments, collapse the footage into a top card (`frameFootage({card: 1})`) and use
  the bottom half.
- **9:16 safe zones** (Reels / TikTok / Shorts UI): the top 8 %, the bottom 20 % and the right 12 % of the lower half
  are covered by buttons and captions. Nothing important goes there (`review.py` shades them red).
- **Captions** sit at the profile's position. Move them when a graphic takes their spot (pass `y` to `run`), and
  hide them (`hidden`) while a graphic shows the same words in big type.
- **Contrast.** On busy footage, cards are solid (white `--card` or dark `--panel`) with a soft shadow, and white
  text gets a shadow. Pick white or dark caption text based on what's behind it.
- **Colour.** The user's accent for emphasis (key words, the number that matters, the active state). A product's own
  colours and logo when that product is on screen. Never redraw a real product's UI badly: if you mock it up, use
  its real colours, icons and type, and keep it simple.

## 5. Patterns that work on talking heads

Pick per beat from what's being said. Vary them: don't use the same pattern three times in a row.

| They say… | Show |
|---|---|
| a number, time or price | a counter that rolls to the value and lands on the word (accent colour on landing) |
| a list ("captions, graphics and sound") | checklist rows popping in on each word, with ticks |
| a tool, app or brand | its logo or icon + name chip in its own colours, or a small faithful UI panel |
| a process ("drag it in and it does everything") | a mini UI scene: footage collapses to a top card, a cursor drags a file into a window, rows tick |
| a contrast ("instead of hiring an editor") | the "old way" card (invoice, timeline, clock) that gets struck through |
| a bold claim / hook | big kinetic type (2–4 words) in the chest band, with the key word in the accent and a punch-in |
| "comment X" | a comment box typing the keyword, then a send-button press |
| "follow" | a follow button the cursor clicks, flipping to "Following ✓" |
| a question to the viewer | the question as big type, then the answer replacing it |
| a before/after | a split-screen card with labels, a wipe between them |

Camera: start the hook slightly punched in (1.08 → 1.0 on frame 0), punch in 1.05–1.09 on the strongest claims and
jump cuts, and come back out on the next beat. Use `R.track` so the moves chain smoothly.

## 6. Gotchas

- An element created with `R.make` but never `keep`/`set` doesn't animate. A scene root hides everything outside
  its window automatically.
- `R.hit` leads the time by about half the spring, so a card is visibly there ON the word. Use `R.spring` for exits.
- When the shotlist puts two scenes at the same spot, the outgoing one's `tOut` must be at least 0.15 s before the
  incoming one's `tIn`.
- Fonts that fail to load log `font not loaded` in the render output. Fix the `@font-face` URL in `film/index.html`.
- Footage frozen in a render means `assets/foot` is incomplete or `project.json.footage.count` is wrong. Re-run `cut.py`.
- Captions show words from `edit/words.json`. Fix spelling there (keep the times), then run `sync.py`.
- The [incremental builder](build.md) tracks revisions and avoids recapturing the picture for audio-only changes.
